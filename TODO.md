# HI Acceptor — delivery outcomes

- [x] **Free, ungated, local-first product** — “make it completely free”; no paid activation, account activation, Telegram/WhatsApp activation or messaging, subscription, unlock, or login is required. Rules and local request status are stored on-device; screen text is not sent to a HI Acceptor backend.
- [x] **Ride-filter settings** — Configure minimum/maximum fare, maximum pickup time, region/currency, supported driver app, excluded destination terms, and preferred terms. Seeded examples are SAR 12–80, five-minute pickup, exclusions `Airport`/`مطار`, and preferred `hamara`. Preferred terms never override hard filters.
- [ ] **Android auto-accept integration** — The Kotlin Accessibility service and Expo module are implemented for Jeeny Driver (`me.com.easytaxista`) and Bolt Driver (`ee.mtakso.driver`), with fail-closed parsing and an explicit accept-control check. Native compile/device validation remains open because this sandbox has no Android SDK; test a native Android build and real supported app screens before claiming a verified release.
- [x] **Transparent Android permission and operation controls** — Explain Accessibility access, link to Android settings, and require both Android permission and explicit Start. Do not direct users to disable Play Protect or other Android security protections.
- [x] **Status, activity, and local notifications** — Show active/permission/last-event status, local simulator history, and a native notification after an accepted match when Android notification permission is granted. Activity is stored on-device and can be cleared.
- [x] **Rule simulator and buildable app source** — The web preview is labeled simulator-only; 8 rule tests pass, full checks pass, Expo web export passes, Android prebuild generates the Accessibility manifest, and local-module autolinking resolves the Kotlin module. Android APK/device validation is still pending.
